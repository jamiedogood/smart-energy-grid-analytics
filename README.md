# Smart Energy Grid Analytics

Smart-meter analytics pipeline for 4,000 meters (Advanced Big Data Analytics, Assignment I).
MQTT ingestion with EMQX, storage benchmarks in TimescaleDB (chunk intervals, compression,
continuous aggregates), Grafana dashboards, anomaly detection and day-ahead demand forecasting.
Everything runs in Docker Compose. Nothing except Docker is installed on the host.

Repository: https://github.com/jamiedogood/smart-energy-grid-analytics

## Architecture

```
smart_meter_simulator.py -> mqtt_publisher.py -> EMQX (MQTT, QoS 1) -> mqtt_subscriber.py -> energy_live      (pilot, 1.3)
smart_meter_simulator.py -> load_full_stream.py (PostgreSQL COPY, 100k-row batches) -> energy_readings (full load, 2.1)
energy_readings -> chunk / compression experiments, continuous aggregates -> Grafana dashboards, Python analysis
```

| Container | Image | Purpose |
|---|---|---|
| emqx | emqx/emqx:5.8.6 | MQTT broker (1883; dashboard on 18083) |
| timescaledb | timescale/timescaledb:latest-pg16 (PostgreSQL 16.15, TimescaleDB 2.30.2) | Database `smartgrid`; limits 4 CPUs, 4 GB RAM, 1 GB shm |
| app | built from `Dockerfile` (Python 3.12, psql, Chromium, Playwright) | Runs every script in `src/` |
| grafana | grafana/grafana-oss:11.3.0 | Raw and Aggregate dashboards (3000) |

## 1. Setup

Prerequisites: Docker Desktop with about 10 GB free disk space.

```powershell
git clone https://github.com/jamiedogood/smart-energy-grid-analytics.git
cd smart-energy-grid-analytics
Copy-Item .env.example .env      # then edit .env: set PG_PASSWORD, EMQX_DASHBOARD_PASSWORD, GRAFANA_ADMIN_PASSWORD
docker compose up -d --build
docker compose ps                # emqx, timescaledb, app, grafana all running
```

Every Python script runs inside the `app` container, which reaches the other containers by
service name (`emqx:1883`, `timescaledb:5432`). Connection settings come from environment
variables set in `docker-compose.yml`; there are no secrets in code.

## 3. Pilot run (Section 1.3)

Uses two terminals. Expected result: 2,000 at all four stages.

```powershell
# Terminal 1 - empty the pilot table, then start the subscriber and wait for "READY"
docker compose exec app psql -c "TRUNCATE energy_live; SELECT count(*) AS rows_before FROM energy_live;"
docker compose exec app python src/mqtt_subscriber.py

# Terminal 2 - publish the first 2,000 generator readings (QoS 1, not retained)
docker compose exec app python src/mqtt_publisher.py

# After the subscriber prints its summary (about 15 s after publishing ends)
docker compose exec app psql -c "SELECT count(*) AS stored_rows, count(DISTINCT (meter_id, event_time)) AS unique_pairs FROM energy_live;"
```

Four counts: dictionaries taken (publisher), messages acknowledged by the broker (publisher),
messages received (subscriber), rows in `energy_live` (final query). Logs: `logs/publisher.log`,
`logs/subscriber.log`.

## 4. Regenerating the dataset

The full dataset (10,696,848 readings) is not stored in the repository. The generator creates the
same data in memory on every run, and `src/load_full_stream.py` streams it straight into
`energy_readings` with PostgreSQL `COPY` (about 100 s). No intermediate CSV is created.
To rebuild from scratch: start the containers, run Sections 1.1-1.2, then 2.1 onward in the order
above. To reload only the readings: `docker compose exec app python src/load_full_stream.py --truncate`.

## 6. Generator integrity

`smart_meter_simulator.py` is the issued file, unchanged. Verify with:

```powershell
Get-FileHash .\smart_meter_simulator.py -Algorithm SHA256
```
